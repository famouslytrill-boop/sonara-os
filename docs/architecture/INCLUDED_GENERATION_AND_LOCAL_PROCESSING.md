## What customers can use

Creator Studio's existing Generation Studio page now enforces paid Creator access and displays its organization's included generation budget, reserved usage and renewal date. The existing $5 starting allowance becomes $5 for each verified monthly billing period, or $60 for a verified annual period. This is usage covered by the subscription, not an additional customer charge or a top-up purchase. Provider rate limits and consent requirements remain. Usage does not roll over. All seats share the organization pool. Other subscription workspaces are not implicitly granted Creator access.

The billing webhook accepts both legacy subscription periods and Stripe's current item-level periods. Inconsistent item periods are refused. A missing, stale or expired period cannot grant compute; verification outages return 503. Exhausted included usage returns 429 and says it renews with the subscription, with no extra purchase required. The generation routes do not use the older lifetime credit balance for new jobs.

`generation_usage_reservations` and the server-only, security-invoker `generation_usage` RPC serialize reservations, settlement and release with a transaction advisory lock per organization. The database reads the verified Stripe subscription itself and determines the budget; request bodies cannot grant a budget or choose a tenant. New jobs receive server-generated UUIDs before reserving compute. The reservation happens before job insertion or provider dispatch. Settlement inserts the idempotent draw and consumes its hold in one transaction. Measured usage is preferred; estimated usage is explicitly identified. A completed asset stays available if our settlement fails, while its hold remains and a billing gap is reported. Actual usage above an estimate consumes the pool and blocks later work; it does not create an extra invoice. Failed and locally cancelled jobs are absorbed and release their holds. Local cancellation does not claim provider-side cancellation.

Ambiguous database insertion failures retain their hold. A definitively rejected insertion releases it after the database confirms no job exists. There is no time-based release that could let an active job spend its allowance twice. An operator must reconcile abandoned holds against authoritative job/provider state. Pre-migration jobs use the existing idempotent ledger path. Legacy draws during the current period count toward its budget; overlapping plan changes cannot reset usage. Old period work settles against its original reservation, rather than silently charging the renewal period.

Creator Studio also processes local PNG, JPEG and WebP images on the user's device. Upload a file in the Generation Studio page, choose brightness from 0–200%, process and download a PNG. An integer WebGPU compute shader and chunked CPU fallback apply identical channel scaling, preserve alpha, and keep the original pixels for repeat edits. Capability detection is truthful. The surface reports which engine actually ran. Limits are 20 MB, four megapixels and 4096 pixels per side; the GPU buffers and temporary download URLs are released. No upload, remote inference, camera access or allowance draw is performed. This is image processing, not a local generative model or a native operating system.
