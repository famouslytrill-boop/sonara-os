## Portfolio rules

- Keep the connected path from business launch, to creator operations, to measurable growth.
- Prefer complete governed workflows over large collections of disconnected features.
- Preserve the Free, Starter, Core, and Pro plan families. This catalog does not create or change Stripe prices.
- A paid plan floor is only honest where the server enforces an entitlement for that product family. Where it does not, price the product free or map the entitlement — do not publish a plan that buys nothing.
- Keep provider-backed execution setup-gated and approval-gated.
- Do not present `validation_required`, `planned`, or `setup_required` products as complete.
- Preserve the done-for-you service catalog alongside the software product catalog.

## Where this lives in the code

- `lib/catalog/*.cjs` holds the definitions. `lib/sonara-recommended-product-catalog.cjs` assembles them and computes the execution boundary.
- `lib/sonara-paid-access.cjs` names the entitlement keys the server actually enforces. A paid product outside that map cannot open, by construction.
- `scripts/generate-catalog-sync-migration.cjs` writes the migration that publishes these rows to `service_catalog_items` and retires the ones the catalog has dropped.
- `scripts/verify-production-product-catalog.mjs` compares the live database against this catalog and gates the production deploy on it. Its expected counts are read from the catalog, not written down a second time.
- `/service-catalog` merges the database rows over these definitions, so the database wins on anything it holds.

## Paid access

The server reads active `billing_entitlements` first, then active or trialing
`billing_subscriptions`. Missing or unmapped billing state fails closed.

This catalog once defined "paid access is verified" as `planFloor === "free"`,
which made every paid product permanently shut while reporting the state as
pending work. It is now the question the code can actually answer: whether
`lib/sonara-paid-access.cjs` maps an entitlement key for the product's family.

Current enforcement: sonara_industries not enforced, business_builder enforced, creator_studio enforced, growth_studio enforced.

A positive end-to-end test — a real production account on the intended plan
granted access, and a lower-plan account denied — has not been run. That is
recorded in `docs/SHIP_READINESS.md` as owner work, and it is separate from
whether the mapping exists.
