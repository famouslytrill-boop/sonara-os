SONARA can map its reusable skills and Prompt Library metadata into that model, but Batch 8 does not claim a production SONARA ChatGPT plugin exists.

## Correctness authority

### Booking calendar revision sequence — fix required

`lib/sonara-calendar-invite.cjs` emits an iCalendar `SEQUENCE` from `booking.calendar_sequence`. The current governed source search identifies the reader but no writer. Until a persisted monotonic sequence is written on relevant booking revisions, SONARA should not claim that repeated calendar exports reliably supersede prior revisions in every client.

This needs a storage/update design, not a cosmetic fallback derived from a timestamp. A real fix should survive two updates close together and concurrent edits rather than merely changing the number most of the time.

### Growth campaign recipient snapshot — review required

The current sender/dispatcher contract is intentionally strong: the dispatcher accepts the authorized decision rather than the raw input list. Before adding queued or multi-invocation campaign execution, the exact owner-approved recipient decision must remain the exact set dispatched across retry/resume boundaries. A later audience re-query must never silently become the approval source.

### Cross-agent authority — active rule

Claude, ChatGPT, Codex, plugins, skills, MCP-compatible metadata, and future agent adapters inherit SONARA's own tenant isolation, authorization, audit, approval, and release controls. They are not alternate routes around those controls.

### License boundary — active rule

Permissive, reciprocal, mixed, source-available, model-weight, dataset, template, generated-asset, and hosted-service rights remain separate questions. “Research only” is not a substitute for verified adoption rights.
