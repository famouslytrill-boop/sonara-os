# SONARA formula-evidence skill

Use for any calculation, algorithm, projection, score or source-grounded mathematical assertion. This skill is a discovery and validation procedure, not an execution grant.

1. Read `AGENTS.md`, `.ai/shared/PROJECT_MEMORY.md` and `.ai/shared/ASSISTANT_KNOWLEDGE_INDEX.md` for repository pointers.
2. Choose an appropriate domain and **source-qualified formula**. Examine `lib/sonara-formula-library.cjs`, `lib/sonara-industry-algorithm-expansion.cjs`, `lib/sonara-formula-engine.cjs`, `lib/sonara-financial-intelligence-formulas.cjs` and other indexed quantitative modules as relevant.
3. Distinguish `research_only`, `registered`, `allowlisted_executable`, `tested` and `production_verified`. A document/SQL registration does not make a calculation callable or correct.
4. Validate the input domain, units, currency, period, dimension, timezone, zero denominators, null values, precision/rounding, authoritative source, provenance, and relevant industry/legal restrictions. Never infer missing values as zero.
5. For executable formulas, use the existing allowlisted deterministic implementation. Do **not** `eval` expressions, run arbitrary spreadsheet formulas/macros, route through an AI provider unnecessarily or invent a mathematical result.
6. Compare expected outputs against independent examples; test malformed, boundary, cross-tenant and missing-input cases. Falsify any added check on a deliberately bad fixture; keep the original unchanged.
7. Report assumptions, input lineage, formula version, computed or unavailable state, and whether it was tested locally or exercised in live production. No formula can authorize payments, trades, legal/medical determinations, destructive changes or deployment.
